# 公文写作与排版

1. 选文种：
   - 向上级请求批准、指示：请示，一文一事，结尾“妥否，请批示”；
   - 向上级汇报工作、反映情况：报告，不夹带请示事项，结尾“特此报告”；
   - 发布、传达要求，或要求下级办理：通知，结尾“特此通知”（正文最后已讲清要求的可不写）；
   - 不相隶属的单位之间商洽、询问、答复：函，结尾“请予函复”或“特此函复”；
   - 记载会议议定事项：纪要。
   用户说的文种不合适时（例如向上级“通知”），说明理由并建议。
2. 要素：发文机关、发文字号（“X政发〔2026〕12号”，用六角括号）、标题（“关于……的通知”）、主送机关（后加全角冒号）、正文、附件说明、发文机关署名、成文日期（阿拉伯数字，“2026年10月28日”）、附注、抄送、印发机关和日期。上行文还要写签发人。用户没给的要素不要编，空着并在回复里列出。
3. 正文结构层次序号依次用“一、”“（一）”“1.”“（1）”，一个层次只有一项时不分层。数字、日期、计量单位写法前后一致。
4. 新起草：word_document create_official 生成符合 GB/T 9704 的 Word 文件（版头、版记、页码、字体字号行距都按标准）；常用文种也可以用 office_template 从模板生成后再改。
5. 已有文件：
   - 只看格式问题：office_read check_official，按页面、字体字号、行距、序号、日期分组告诉用户；
   - 要改格式：word_document fix_official 另存一份调整后的文件（原文件不动），再 check_official 确认剩余问题；
   - 要改内容：word_document revise 用修订模式改，并加批注说明理由，用户在 Word 里逐条接受或拒绝。
6. 语言：庄重、准确、简明，少用形容词；数据和政策依据要有出处，用户材料里没有的不要补。
7. 交付：回复里写文件位置和仍需用户补的要素（文号、签发人、印章等）；电脑上没有方正小标宋、仿宋_GB2312 等字体时，提醒用户 Word 会用替代字体显示，打印前装上字体。
